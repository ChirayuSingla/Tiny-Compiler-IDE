# Testing

This file is generated by `python tools/build_report.py`; the results below come from actually running the commands (2026-10-15, Python 3.9.0, Windows 11).

## How to run

```powershell
python -m unittest discover -s tests -t . -v
```

No third-party packages are needed. `python -m pytest tests` also works if pytest is installed.

## Test plan

| Level | Module | Purpose |
|---|---|---|
| Unit | `tests/test_lexer.py` | valid and invalid tokens, positions, comments, strings |
| Unit | `tests/test_parser.py` | precedence, associativity, valid/invalid syntax, recovery, unsupported constructs |
| Unit | `tests/test_semantics.py` | declarations, scopes, types, constant division by zero, warnings |
| Unit | `tests/test_ir.py` | exact three-address code, labels, short-circuit, TAC interpreter |
| Unit | `tests/test_codegen_vm.py` | exact stack code, execution, input, run-time errors, random differential test |
| End-to-end | `tests/test_end_to_end.py` | every example through the CLI, every CLI option, exit codes |

Expected outputs in `examples/*.expected` were checked by hand (for example `-7 / 3 = -2`, `-7 % 3 = -1`, sum 1..10 = 55, gcd(84, 36) = 12) before being used as references. Two manual mutation spot-checks (breaking integer division, and removing `%` from the multiplicative level of the parser) made the suite fail, confirming that the tests detect such bugs.
